# Skill: bug-fix

## 名称

bug-fix

## 使用时机

当需要修复已确认的 bug 时使用。包括：
- 测试失败后的代码修复
- 用户报告的缺陷修复
- 集成过程中发现的问题修复

## 输入

- Bug 描述（复现步骤、预期行为、实际行为）
- 相关代码文件和测试
- 关联的需求或设计文档（如有）

## 执行步骤

1. **复现**：确认 bug 可以稳定复现
2. **定位**：缩小问题范围到具体文件/函数
3. **分析**：理解根因，不只是修补症状
4. **修复**：最小化变更，只改必须改的
5. **验证**：运行相关测试确认修复有效且无回归
6. **记录**：说明根因和修复方式

## 必须遵守

- 修复必须针对根因，不是绕过症状
- 每次修复必须附带验证步骤（测试或手动验证）
- 不引入未经批准的新依赖或架构变更
- 不修改测试预期来让测试通过

## 禁止

- 不写业务代码来掩盖 bug
- 不删除失败的测试
- 不在没有理解根因的情况下反复尝试修改
- 不扩大修复范围（顺手重构、添加新功能）

## 验证

- 原有 bug 不再复现
- 相关测试全部通过
- 无新增回归

## 输出

- 修复的代码变更
- 验证结果（测试输出或手动验证记录）
- 根因说明（一行描述）
