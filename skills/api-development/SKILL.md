# Skill：api-development

## 名称

api-development

## 描述

负责 API 契约的设计、文档化、实现和测试；在技术决策形成前，不绑定具体框架。

## 适用场景

- 需要新的 API 契约。
- 现有 API 契约需要变更。
- 需要定义请求/响应结构、参数校验、错误或兼容性规则。
- 需要创建或审查 API 测试和接口文档。

## 输入

- 已批准的产品需求或模块需求。
- `docs/modules/` 下的相关模块文档。
- 架构规范或 ADR。
- 现有 API 契约，如有。

## 前置条件

- API 是为满足已批准需求而存在。
- API 风格和框架选择已经确定，或当前工作明确保持框架无关。
- 向后兼容预期已知，或明确标记为 TBD。

## 执行步骤

1. 识别 API 支持的用户流程或系统流程。
2. 用框架无关的语言定义端点或操作目的。
3. 指定请求字段、响应字段、校验规则和示例。
4. 定义错误场景、错误码和错误响应结构。
5. 如适用，记录认证、授权、幂等、分页、过滤和限流规则。
6. 检查与现有契约的兼容性。
7. 定义 API 测试，覆盖成功、校验失败、授权失败和边界场景。
8. 在实现前或实现同时更新模块 API 文档。

## 检查项

- API 行为映射到已批准的验收标准。
- 请求和响应字段具备清晰类型、必填/可选状态和校验规则。
- 错误行为已文档化且可测试。
- 除非已有 ADR，否则不假设具体框架实现。
- 已说明兼容性影响。

## 输出

- API 设计或更新后的 API 文档。
- 校验和错误行为说明。
- API 测试计划或测试。
- 兼容性说明和待确认问题。

## Definition of Done

- API 契约已文档化。
- 测试覆盖正常路径和失败路径。
- 校验和错误处理保持一致。
- 已说明兼容性风险。
- 所需架构决策已记录，或已标记为阻塞项。

## 失败处理

- 如果必要行为不清楚，记录不确定性并在实现前停止。
- 如果契约变更可能破坏客户端，必须请求批准。
- 如果框架约束会影响契约设计，记录或请求 ADR。

## 必须停止并询问用户的情况

- 需要在未批准需求的情况下创建或变更公开 API 契约。
- 认证、授权或权限行为不清楚。
- 错误语义需要产品或兼容性决策。
- 必须选择 API 风格或框架。
